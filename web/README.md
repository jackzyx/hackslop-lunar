# Sun Shade web app

The navigation map fills the full width of its panel. A ResizeObserver shares the
panel aspect ratio with the terrain renderer and SVG overlay, so the wide desktop
view reveals more ground without stretching craters or distance rings. The whole
region view fits within the DEM extent to avoid empty side strips. Tablets use a
wide map and phones keep a square map. GPU and worker rendering both support the
same rectangular projection.

Shadow-map performance: WebGL2 renders the terrain ray march on the GPU. It draws
at 256 px high while the delay slider is held, then resolves to 512 px high on release;
the width follows the panel aspect ratio.
Requests are coalesced to animation frames. If WebGL2 is unavailable or its context
is lost, a Web Worker draws a 144 px interaction preview and a 360 px final image,
keeping the UI thread free. The fallback keeps only the newest queued request.
The 500 m source terrain and the horizon-based site metrics are unchanged.
Planned-date verdicts and chart bounds are cached; detailed charts use deferred
updates so they do not take priority over the slider and shadow map.

Browser regression check: install Playwright locally with
`npm.cmd install --prefix .slide-tools playwright` from the repository root, start
the dev server on port 5174, then run `node scripts/check-shadow-browser.cjs`.
It compares GPU pixels with the CPU reference for flat, dark, wall and real-terrain
scenes, and checks keyboard updates, pointer release and worker fallback. Chrome
is used on Windows; `CHROME_PATH` and `TEST_URL` can override the browser and URL.
`node scripts/bench-slider.cjs` repeats the slider drag benchmark on port 5174.

The shared navigation switches between **Compare sites** (`#compare`) and
**About** (`#about`) without resetting the selected date or sites. The About page
uses the same amber HUD theme, real terrain rendering, scroll reveals and a
searchable public bibliography (`#about-sources`). Its animations can be paused
and respect reduced-motion preferences.
Public source entries live in `src/lib/sources.js`; keep them in sync with the
project reference log when data, imagery or tools change.

Intro visuals use a bundled 4096 × 2048 NASA lunar albedo texture, a
viewport-sized globe raster (768–1536 px), and an 800–1280 px terrain render.
Critical dark styles and a lightweight orbital visual live directly in `index.html`,
so the initial page does not flash white while JavaScript or styles load. The intro
starts from a small `intro-scene.json` generated by Vite from the actual default
landing data; it does not wait for the full planner/ephemeris module. The planner
is prefetched, then evaluated when the camera has reached its final terrain view.
The overlay reveals the planner only after it is mounted.

Image preparation runs in `intro.worker.js`, with one prepared scene cached for
replay. A small globe and terrain preview arrive first; full-resolution images
replace them in the background while playback continues. Skip works before the
main application loads. Worker-disabled browsers prepare smaller terrain tiles
cooperatively. The playback clock caps long-frame advances
and pauses in hidden tabs instead of jumping ahead. Close-up image draws are
cropped to the viewport, and the display canvas is capped at 8 million pixels.
`node scripts/check-intro-browser.cjs` checks full playback, synthetic stalls,
cached replay and skipping during preparation (dev server on port 5174).
`node scripts/check-startup-browser.cjs` additionally blocks the JavaScript bundle
to verify the dark first paint, delays planner/terrain downloads to verify the
intro starts independently, and checks the final handoff. Set `TEST_URL` to a
Vite preview URL to check the built site with the same test.
The final camera fits the detailed terrain to every screen corner, including wide
and portrait displays. During approach, a broad terrain feather blends the local
tile into the globe; full-contrast terrain is restored only as it covers the whole
viewport. This removes the sharp circular tile boundary without changing the
underlying terrain or increasing download size. A comparison frame is saved in
`docs/intro-blend-preview.png`. The surface-data resolution remains 500 m; rendering at
more pixels does not add new scientific terrain detail. Visual source and credit:
NASA's Scientific Visualization Studio, [CGI Moon Kit](https://svs.gsfc.nasa.gov/4720/).
The texture is served locally, so no external imagery connection is needed at runtime.
Updated browser captures are in `docs/intro-approach-updated.png` and
`docs/intro-terrain-updated.png`.

React + Tailwind + shadcn/ui, styled as a retro amber HUD (dark only, for the projector).
The console fits one 1280x720 screen: a launch-slip slider (-60 to +60 days), the STARS line
(`src/domain/narrator.js`, one sentence built from the computed numbers), and site 1 | shadow map |
site 2. Per site: sunlit hours in the 30 days after landing, a status (NOMINAL / MARGINAL /
CRITICAL), Sun and Earth bars, a verdict, longest dark gap, next sunset or Earthset. Under the
console, tabs: the skylines and 30-day strips, the JPL Horizons validation, what we do not model.
Static, no backend, runs offline.

Code: `src/App.jsx` (state and layout), `src/components/` (SiteCard, ShadowMap, DetailTabs, and
the shadcn components in `ui/`, which we own and restyle), `src/lib/` (data, chart SVG,
validation formatting), `src/index.css` (theme tokens and HUD styles). The maths stays in plain
JS with node tests: `metrics.js`, `shadow.js`, `intro.js`, `narrator.js`.

The map's terrain is `public/terrain_500m.bin` (LOLA 80 m DEM averaged to 500 m, ±250 km,
int16 metres), made by `python scripts/export_terrain.py`. Its Sun direction is rebuilt
for the landing instant from the first chosen site's Sun azimuth and elevation in the
data file. The site numbers come from the horizon masks, not from this map.

```bash
cd web && npm install
npm run dev      # http://localhost:5173
npm test         # metrics unit tests (node:test, no extra deps)
npm run build    # dist/ (relative paths: any static server, USB stick, Pages subpath)
python dist/serve.py   # USB stick / offline: serves dist on http://127.0.0.1:8000 and opens it (file:// pages can't load the app)
npm run mock     # WARNING: overwrites src/mock-data.json (now the real SPICE table) with invented data
```

## Precomputed lunar ephemeris

`src/mock-data.json` contains the hourly SPICE ephemeris and LOLA horizon masks for
the eight curated sites. The browser computes the metrics from this file and shows
the **MOCK DATA** badge when its `mock` flag is true. To restore or regenerate the
SPICE data, run `python science/lunar_ephemeris.py` from the repo root with the
kernels and the 80 m and 240 m LOLA terrain downloaded.

| Key | Shape |
|---|---|
| `sites[]` | `id`, `name`, `kind`, `mission` (mission or programme label from Story's site list, or `null`), `lat`, `lon` (deg, east-positive), `mast_m`, `az_step_deg` (0.5), `horizon` (720 skyline elevations in deg, azimuth 0, 0.5 ... 359.5 clockwise from north) |
| `ephemeris` | `start_utc`, `step_s` (3600), `count`, `frame` (`MOON_ME`), and `sites[id]` = `{sun_az, sun_el, earth_az, earth_el}`, each `count` values in deg (az clockwise from north) |
| `rig` | `sub_solar_lat` and `sub_solar_lon`, each `count` values in deg in the same hourly order, with east-positive longitude in [0, 360) |

The table covers 52,584 UTC hours from 2025-01-01 00:00 to 2030-12-31 23:00. The
observer's position includes the LOLA ground height and the 2 m mast. The SPICE
generator checks Sun and Earth against one Horizons epoch at (0° E, 89.9° S,
0 km altitude) before replacing the data.

The validation table and the header line read `src/validation.json` (Science writes it;
`null` shows as "not yet measured"): `queried` (date string), `pass_deg` (0.01), `rows[]` =
`{site, body, max_del_deg, max_daz_cos_deg, hours, start, stop}` (deg, ISO dates), and
`checks[]` = `{id, label, result}` (result is a short sentence, e.g. "0.087° dip, within 0.001°").
The header shows the worst row as "within X° of JPL Horizons", so never type numbers into the HTML.

The date picker is limited so that planned date ± 60 days plus the 30-day window stays
inside the table.

Definitions used on screen: sunlit hours = sum of the visible fraction of the 0.53° disc;
dark = no part of the disc visible; Earth in view = Earth centre above the skyline (line of
sight only); verdict = first delay of 0 to 60 days whose 30-day window gets less than half
sunlight (360 of 720 h). Thresholds live at the top of `src/domain/metrics.js`.
